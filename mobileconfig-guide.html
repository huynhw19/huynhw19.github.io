A beginner’s guide

Learn about mobileconfig

A .mobileconfig file is an Apple configuration profile. It packages settings that a compatible iPhone, iPad, or Mac can apply, such as Wi-Fi or DNS settings. This guide explains the basics and how to review a profile safely.

Important: A profile can change important device or network settings. Only install one from a source you trust, and inspect its contents before accepting it. ConfigKit is an independent demo, not an Apple service.

Profiles and payloads

A configuration profile is a container. It has profile-level information and one or more payloads. Each payload describes a particular type of setting. For example, a profile might contain a Wi-Fi payload and a web clip payload. The device decides whether it supports each payload and setting.

A common downloadable profile uses the .mobileconfig filename extension and is represented as an XML property list (plist). The extension alone does not guarantee that the contents are valid, safe, signed, or supported by your device.

How the file is organized

At a high level, an XML profile is a plist dictionary. The outer configuration identifies the profile and contains an array of payload dictionaries:

<plist version="1.0">
  <dict>
    <key>PayloadType</key>
    <string>Configuration</string>
    <key>PayloadIdentifier</key>
    <string>com.example.profile</string>
    <key>PayloadUUID</key>
    <string>A-UNIQUE-UUID-VALUE</string>
    <key>PayloadContent</key>
    <array>
      <!-- One or more payload dictionaries go here. -->
    </array>
  </dict>
</plist>

This is a teaching outline, not a complete installable profile. Real payloads require the keys and values defined for their specific payload type. XML must also be correctly escaped and formatted.

Common fields
  • PayloadType tells the operating system what kind of profile or payload it is.
  • PayloadIdentifier is a reverse-DNS-style identifier used to identify the profile or payload. Choose a stable, distinctive value for your own profiles.
  • PayloadUUID is a unique identifier for that profile or payload. A profile and its payloads have their own identifiers.
  • PayloadVersion indicates the payload format version; the expected value is defined by the payload specification.
  • PayloadContent holds the profile’s payloads.

Unsigned and signed profiles

A profile can be unsigned or cryptographically signed. Signing can help a recipient verify who signed the profile and whether it changed after signing; it does not make an unsafe configuration safe. A valid signature also does not replace reviewing the settings and trusting the source. ConfigKit’s browser builders generate unsigned examples.

Review before installing

  1. Confirm who provided the file and why you need it. Don’t install unexpected profiles or profiles from untrusted links.
  2. Inspect the profile using a trusted device interface or a local inspection tool. Check every payload, identifier, URL, server, certificate, and restriction.
  3. Look for sensitive information. Wi-Fi passwords and other secrets may be present in a profile file; treat it like a credential and do not post or share it publicly.
  4. Check compatibility and impact for your exact OS version and whether your device is personally owned or organization-managed.
  5. Install only if you understand and accept what it changes. Follow the prompts on your device and verify the resulting settings afterward.
Do not use a sample as a deployment recipe. Profiles that affect certificates, VPNs, proxies, filters, restrictions, or managed-device enrollment can have significant security and privacy consequences.

Removing a profile

When appropriate, remove a profile through your device’s profile or device-management settings. The exact menus vary by OS version. Removing a profile may also remove settings it installed, and a profile managed by an employer or school may be controlled by that organization. Check with the administrator before removing a managed profile.
