⌘ ConfigKit · OAuth Apps

ConfigKit OAuth developer guide

Connect your application to ConfigKit accounts with OAuth 2.1 authorization code flow and PKCE.

ConfigKit-specific permissions: In addition to standard OIDC scopes, registered apps can request account email, profile, ConfigKit Mail, Drive metadata, XML, forms, achievements, App Store and Tool Studio permissions. These are stored as a separate permission manifest and enforced by RLS; standard OAuth scopes alone do not grant database access. App owners can edit their own drafts and reveal their own approved confidential app credentials. Each user must approve the app on the ConfigKit consent screen.

ConfigKit AI MCP endpoint

The authenticated MCP endpoint is https://gwhqnqzzlgslwgijkkpt.supabase.co/functions/v1/configkit-ai-testing. It advertises OAuth protected-resource metadata at /oauth-protected-resource, accepts approved OAuth app tokens, and filters its tools by the ConfigKit permissions attached by the custom access-token hook. Enable the OAuth 2.1 server and select public.configkit_oauth_access_token_hook in Supabase Auth Hooks before connecting an OAuth MCP client.

Current integration scope: ConfigKit OAuth currently supports identity sign-in and standard OIDC scopes only. OAuth-issued tokens are blocked from ConfigKit public database tables, Storage and privileged RPCs by default. Custom API permissions and app-specific data scopes are not yet available.

1. Register your app

  1. Open OAuth Apps and register your application.
  2. Enter the exact HTTPS callback URL your app will use.
  3. Select only the standard identity scopes you need.
  4. Submit for review. After approval, copy the provider Client ID shown in your app card.

3. Start authorization (PKCE S256)

Generate a cryptographically random verifier, derive its SHA-256 challenge, and store the verifier in the user's server-side session or secure session storage. Always generate and verify a random state value.

const verifierBytes = crypto.getRandomValues(new Uint8Array(32));
const verifier = btoa(String.fromCharCode(...verifierBytes))
  .replace(/\\+/g, '-').replace(/\\//g, '_').replace(/=/g, '');

const digest = await crypto.subtle.digest(
  'SHA-256', new TextEncoder().encode(verifier)
);
const challenge = btoa(String.fromCharCode(...new Uint8Array(digest)))
  .replace(/\\+/g, '-').replace(/\\//g, '_').replace(/=/g, '');

const state = crypto.randomUUID();
sessionStorage.setItem('configkit_pkce_verifier', verifier);
sessionStorage.setItem('configkit_oauth_state', state);

const authorize = new URL(
  'https://gwhqnqzzlgslwgijkkpt.supabase.co/auth/v1/oauth/authorize'
);
authorize.search = new URLSearchParams({
  response_type: 'code',
  client_id: 'YOUR_APPROVED_CLIENT_ID',
  redirect_uri: 'https://your-app.example/callback',
  scope: 'openid email profile',
  state,
  code_challenge: challenge,
  code_challenge_method: 'S256'
});
location.assign(authorize);

4. Exchange the code

On your callback route, verify that returned state exactly matches the stored value. Then exchange the one-time authorization code using the same redirect URI and the original verifier.

const params = new URLSearchParams(location.search);
const code = params.get('code');
if (!code || params.get('state') !== sessionStorage.getItem('configkit_oauth_state')) {
  throw new Error('Invalid OAuth callback state');
}

const response = await fetch(
  'https://gwhqnqzzlgslwgijkkpt.supabase.co/auth/v1/oauth/token',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
    body: new URLSearchParams({
      grant_type: 'authorization_code',
      client_id: 'YOUR_APPROVED_CLIENT_ID',
      redirect_uri: 'https://your-app.example/callback',
      code,
      code_verifier: sessionStorage.getItem('configkit_pkce_verifier')
    })
  }
);
if (!response.ok) throw new Error('Token exchange failed');
const tokens = await response.json();

5. Read the signed-in identity

const response = await fetch(
  'https://gwhqnqzzlgslwgijkkpt.supabase.co/auth/v1/oauth/userinfo',
  { headers: { Authorization: 'Bearer ' + tokens.access_token } }
);
const identity = await response.json();

Store refresh tokens securely. Never put secrets in browser code, URLs, logs or source control. Validate JWT signatures, issuer, audience and expiry using the published JWKS. Refresh tokens should be rotated when a new one is returned.
