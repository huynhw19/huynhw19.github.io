# Set up the builder discussion and shared profiles

The discussion page is available to signed-in users and stores posts/comments in the Supabase project used for OAuth. It also supports a signed-in community file feed for `.mobileconfig` uploads.

## 1) Enable the tables

In the Supabase SQL Editor, run:

```sql
create table if not exists public.builder_discussions (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  title text not null check (char_length(title) between 1 and 120),
  body text not null check (char_length(body) between 1 and 5000),
  created_at timestamptz not null default now()
);

create table if not exists public.builder_discussion_comments (
  id uuid primary key default gen_random_uuid(),
  discussion_id uuid not null references public.builder_discussions(id) on delete cascade,
  user_id uuid not null references auth.users(id) on delete cascade,
  body text not null check (char_length(body) between 1 and 2000),
  created_at timestamptz not null default now()
);

create table if not exists public.mobileconfig_posts (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  title text not null check (char_length(title) between 1 and 120),
  description text not null check (char_length(description) between 1 and 5000),
  filename text not null,
  storage_path text not null,
  mime_type text not null default 'application/x-apple-aspen-config',
  file_size bigint not null default 0,
  created_at timestamptz not null default now()
);

create table if not exists public.user_follows (
  follower_id uuid not null references auth.users(id) on delete cascade,
  following_id uuid not null references auth.users(id) on delete cascade,
  created_at timestamptz not null default now(),
  primary key (follower_id, following_id)
);

alter table public.builder_discussions enable row level security;
alter table public.builder_discussion_comments enable row level security;
alter table public.mobileconfig_posts enable row level security;
alter table public.user_follows enable row level security;

grant select, insert on public.builder_discussions to authenticated;
grant select, insert on public.builder_discussion_comments to authenticated;
grant select, insert on public.mobileconfig_posts to authenticated;
grant select, insert, delete on public.user_follows to authenticated;

create policy "Signed-in users can read discussions"
  on public.builder_discussions for select to authenticated using (true);
create policy "Users can create discussions as themselves"
  on public.builder_discussions for insert to authenticated with check (auth.uid() = user_id);

create policy "Signed-in users can read comments"
  on public.builder_discussion_comments for select to authenticated using (true);
create policy "Users can comment as themselves"
  on public.builder_discussion_comments for insert to authenticated with check (
    auth.uid() = user_id and exists (
      select 1 from public.builder_discussions d where d.id = discussion_id
    )
  );

create policy "Signed-in users can read shared profiles"
  on public.mobileconfig_posts for select to authenticated using (true);
create policy "Users can create shared profiles as themselves"
  on public.mobileconfig_posts for insert to authenticated with check (auth.uid() = user_id);

create policy "Signed-in users can read follow relationships"
  on public.user_follows for select to authenticated using (true);
create policy "Users can follow as themselves"
  on public.user_follows for insert to authenticated with check (auth.uid() = follower_id);
create policy "Users can unfollow as themselves"
  on public.user_follows for delete to authenticated using (auth.uid() = follower_id);
```

## 2) Create the profile upload bucket

In Supabase Storage, create a public bucket named `mobileconfig-shares`.

Suggested bucket settings:
- Public bucket: enabled
- File size limit: set to match your needs, for example 2 MB or 5 MB
- Allowed MIME types: `application/x-apple-aspen-config`, `application/xml`, `text/xml`

Add a storage policy similar to:

```sql
create policy "Public read profile files"
on storage.objects for select
using (bucket_id = 'mobileconfig-shares');

create policy "Authenticated users can upload profile files"
on storage.objects for insert
with check (
  bucket_id = 'mobileconfig-shares'
  and auth.role() = 'authenticated'
);
```

## 3) Deploy and test

Then deploy the site and sign in. The dashboard share form uploads the `.mobileconfig` to the community bucket and inserts its metadata into the public shared profiles feed. The builder discussion page shows the latest uploaded profiles and lets signed-in users follow other creators.

Important: do not upload sensitive credentials, private keys, or personal information. For safety, the profile file should be reviewed before download and installation. A file that contains Wi‑Fi credentials is sensitive and should only be shared with trusted people or organizations.
