## 🌈 What is ConfigKit?

ConfigKit is a browser-based collection of tools and workspaces. It brings together configuration-profile creation, personal organisation, file storage, community publishing, family learning and education features in one place.

The project is designed to work as a static website with browser-side JavaScript and Supabase-backed services for features that need accounts or shared data.

> **Start here:** Visit [huynhw19.github.io](https://huynhw19.github.io/), create an account if you want to use account-based features, confirm your email when prompted, and open your dashboard.

## 📱 Mobileconfig Studio: current features and direction

Mobileconfig Studio is the home for creating Apple configuration profiles in ConfigKit.

**Available today:** the signed-in Studio can generate profiles using its supported Wi-Fi, Web Clip and encrypted DNS (DoH) payloads, preview the generated XML, download a `.mobileconfig` file, and save generated profiles to the private Profile Library. The current community-sharing form publishes a title and description only; it does **not** upload or share the generated profile file or its contents.

**Planned direction — free for everyone with no paid tiers:**

- Create new profiles and import/edit existing `.mobileconfig` files.
- Keep profile generation, editing, validation and downloads free.
- Let signed-in members save, organise, duplicate and manage profile versions in their library.
- Add safer profile sharing through shareable links and QR codes, with clear public/private access controls.
- Expand the payload reference library with explanations, examples and compatibility notes.
- Add validation and safety guidance before download, sharing or installation.
- Make ConfigKit AI a helpful guide for profile creation, editing, validation and safe sharing.

Signing in will support personal saving and sharing features; it will not be a paid upgrade. These are roadmap goals, not claims that every capability is already available. Review every profile before installation and never publish credentials, private keys or other secrets.

For updates and community voting, visit the [ConfigKit Roadmap](https://huynhw19.github.io/roadmap.html#mobileconfig-studio-plan) and [Mobileconfig Studio](https://huynhw19.github.io/mobileconfig-builder.html).

## 📚 Community publishing

ConfigKit has two separate community publishing experiences:

### 📕 Community Book
Members can explore published books and reading lists. Writing access is controlled through the ConfigKit author-approval process; only ConfigKit administrators can approve author applications. See [Community Book documentation](COMMUNITY-BOOK.md).

### 📖 Community Wiki
Signed-in members can create drafts, publish and manage their own articles, and report content that needs review. Published, visible articles can be read publicly. The registered site administrator handles moderation. See [Community Wiki documentation](COMMUNITY-WIKI.md).

Please publish original, useful material. Never include passwords, verification codes, recovery codes, private information or content you do not have permission to share.

---

### Family Hub additions

ConfigKit's Family Dashboard includes a connected Family Hub linking Kids Zone, Kids Messages, Kids Inbox, adult messaging controls and the shared Family Planner. The Family Life Organiser stores meal plans, shopping lists, savings goals, pocket-money notes, routines, feelings check-ins, written memories, celebrations, family activities and learning goals in the `family_life_items` Supabase table. Private family photo albums use the `family_photos` table and non-public `family-albums` Storage bucket; supported uploads are JPEG, PNG, WebP and GIF up to 10 MB. Parent-authored family announcements use `family_announcements` and appear in Kids Inbox for signed-in family members. Both albums and announcements update through Supabase Realtime. These family tables use RLS, family-membership checks, verified-session restrictions and OAuth-client-token blocking; `anon` has no table access. Photo files are delivered with short-lived signed URLs rather than public bucket URLs. Older device-local organiser entries are imported once after the family is connected. Organiser items can be exported as JSON or deleted; deleting an item removes it for the whole family. The Family Planner continues to use `family_shared_items` and refreshes through Realtime. Kids Messages uses its parent-approved friendship/conversation model and refreshes active chats through Realtime. Kids Zone learning progress remains in its existing child-scoped progress tables. Built-in Kids Inbox encouragement notes remain static site content; parent-written announcements are a separate private family feed. The Family Life organiser and family publishing tools are available to verified adult family-account members and do not grant child profiles access to household financial or private organiser notes.

## 👨‍👩‍👧 Family and education

ConfigKit includes dedicated family and education workspaces:

- **Kids Zone:** a searchable catalogue described in the project as 500,000 game entries. The catalogue combines 20 hand-built games with 499,980 generated entries based on 17 reusable learning templates; it is not 500,000 independently hand-built game engines. See [Kids Zone notes](docs/KIDS-ZONE.md).
- **Kids Messages:** parent-approved contacts, linked education relationships and visible parent oversight. The child-facing experience is designed around text, emojis, stickers and bounded drawings rather than open media uploads. See [Kids Messages documentation](KIDS-MESSAGES.md).
- **Family Dashboard:** family setup, child management, learning activities, saved resources and safety controls.
- **Education Dashboard:** lesson planning, student management, teaching resources, learning sessions and education content.

Family and education permissions depend on the account relationships and approvals configured in the app. See [Education tests](EDUCATION-TESTS.md) and the relevant setup guides before configuring a school or family workflow.

## 🔐 Accounts, privacy and safety

ConfigKit uses account authentication for private workspaces and collaborative features. Depending on the feature and account configuration, the app may provide:

- Email/password sign-in and supported connected sign-in providers.
- Passkeys and two-factor authentication options.
- Authenticator recovery codes and session/device management.
- Private user-scoped files and data.
- Role- and relationship-based access for selected community, family and education features.

**Security basics**

1. Use a unique password and protect the email account connected to ConfigKit.
2. Never share passwords, one-time codes, passkeys or recovery codes.
3. Review a configuration profile before installing it. Profiles can change device or network settings.
4. Treat profiles containing Wi-Fi credentials or other private settings as sensitive files.
5. Do not upload secrets or personal information to public community posts.
6. Use only trusted sources for profiles, links, files and community content.

Read the [Account Guide](account-docs.html), [Privacy Policy](privacy.html), [Safety page](safety.html) and [Terms](terms.html).

## 🏗️ Technology

The repository is primarily a static, browser-delivered web application.

| Layer | Project approach |
|---|---|
| Front end | HTML, CSS and browser JavaScript |
| Hosting | GitHub Pages |
| Authentication and application data | Supabase |
| Private file storage | Supabase Storage, including the ConfigKit Drive workspace |
| Server-side workflows | Supabase Edge Functions for selected protected operations |
| Project data and access | PostgreSQL tables, Row Level Security policies and database migrations |

There is no general local build step required for the static pages. Some account-backed features require the matching Supabase project configuration, database migrations, storage policies and deployed Edge Functions.

## 🪟 Windows desktop app

ConfigKit can be packaged as a Windows desktop application using Electron. The desktop app opens the existing live ConfigKit website, so it keeps the same web features, account system and Supabase backend; an internet connection is required.

- Source and build instructions: [WINDOWS-APP.md](WINDOWS-APP.md)
- Build locally with `npm install` then `npm run dist:win`.
- GitHub Actions builds a Windows x64 NSIS `.exe` installer. Run the **Windows desktop app** workflow manually from the Actions tab, then download the `ConfigKit-Windows-Installer` artifact.
- To publish a versioned GitHub Release, push a tag such as `v1.0.0`; the workflow attaches the installer to that release.

The installer is unsigned, so Windows SmartScreen may show an unknown-publisher warning. The app does not bundle a copy of the site or work offline.

## 🧪 Testing and verification

Testing should match the feature being changed:

- Check page loading, navigation and responsive layouts on mobile and desktop browsers.
- Check browser console errors and JavaScript syntax after editing scripts.
- For authenticated features, test with separate accounts and confirm users cannot access one another's private data.
- For Supabase changes, verify Row Level Security, grants, policies, triggers and Edge Function permissions.
- For family and education tools, test the parent, child and teacher permissions independently.
- For profile builders, inspect the generated profile before installation.
- For large Scratch projects and media-heavy pages, test on the actual target device; a successful syntax check does not prove the page fits a mobile browser's memory limits.

A code review or syntax check is not the same as a full live-device or multi-account acceptance test. Check feature-specific documentation for known limitations and test status.
